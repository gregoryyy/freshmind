# RFC: reinforcement, weighted geometry and focal regions

The core reconstruction began with tasks 3.2.1–3.2.3 of [milestone 3](TODO.md#3-add-reinforcement-focus--context), using section 2.2 and equation (1) of [Reinforcement Focus+Context (2005)](literature/rfc@3ia05compact.pdf), page 3. The Java prototype supplies historical context; its synthetic-edge implementation is not reused.

## Scope and ownership

`src/fm/rfc/` owns transient focal centers, settings, derived constraints and force calculations. `src/fm/struct/` supplies persistent graph-owned memberships and `src/fm/cluster/` supplies detached cluster proposals. `TGLayout` gains a generic optional force callback between its ordinary attraction/repulsion and its existing momentum integration. It imports no Freshmind code. Fixed nodes, dragging, locality weighting, displacement limits, damping and scheduling remain TouchGraph responsibilities.

`FreshmindPanel.getRfc()` exposes the controller and attaches it to the current layout. Replacing the layout transfers this attachment; replacing/clearing the graph clears RFC. Destroying the panel detaches the callback and controller. The controller also works with a headless host and an explicitly registered force callback.

Focal constraints never enter `GraphEltSet`, adjacency, semantic metadata or native YAML records. Presentation reads active membership to draw soft yellow halos beneath existing shapes and routed edges; no synthetic relations are painted. Disabling RFC removes its additional forces and halos; it does not rewind positions or erase momentum accumulated during layout. Graph snapshots can still save the resulting positions normally.

## Focal structure

The original implicit primitive is a depth-one star: the visible center and its distinct visible incident neighbors, ignoring direction, self-loops and hidden relations. Extra relations among these nodes remain ordinary graph edges. Parallel/reciprocal center relations produce one branch; the lexically smallest relation ID supplies its radial spring length. This is an explicit multigraph interpretation of the paper's incident branches; the baseline still simulates every semantic relation.

Branches are sorted by `atan2(√λy · (y - center.y), √λx · (x - center.x))` in weighted physical layout coordinates, with node ID as a deterministic tie breaker. Recompute order from the current geometry each force step so crossings do not leave a stale winding. Viewing lenses, rotation, graph spacing and canvas transforms cannot affect this ordering. With optional region exclusion off, isolated centers are valid and add no forces; one branch has only radial reinforcement. A stored focus outside the visible locality is suspended and resumes when shown. Deleting the center clears it, and a new node with the same ID cannot inherit its activation.

## Force law

Let `v = (x, y)` be a branch displacement, `W = diag(λx, λy)`, and `D² = λx x² + λy y²`, as in the weighted distance following paper equation (2). The weights are positive coefficients, not axis scale factors. Equal metric radius describes an ellipse in physical space; `(λx, λy) = (0.25, 1)` permits a horizontal radius twice the vertical radius. No label measurements or viewing transforms enter this metric.

Radial reinforcement adds `−c D Wv`, with `c = (springMultiplier − 1) · rigidity / (edgeLength · 100)`. This is the physical negative gradient of the radial potential `c D³/3`. Unit weights reproduce the original extra TouchGraph attraction exactly, making the representative spring's total attraction equal to the configured multiplier. For non-unit weights only the added reinforcement uses the weighted gradient; the ordinary TouchGraph springs remain unchanged.

For `N >= 2`, each cyclic consecutive branch pair has weighted angular gap `g` and target `t = 2π/N`. Equation (1) gives moment `M = angularStiffness · rigidity · (g − t)`. Apply `+M` and `−M` to the first and second branch. The physical force from a moment is `M √(λx λy) · (−y, x) / max(1, D²)`, with an equal opposite reaction on the center. The factor `√(λx λy)` comes from differentiating the weighted `atan2`; simply computing weighted angles and applying the old unweighted tangent force would not match the energy gradient.

This follows angular potential `k/2 · Σ(g − t)²` outside a soft core of one weighted layout-unit squared. The soft core bounds coincident/near-center behavior; TouchGraph's original random repulsion separates exactly coincident nodes. Established/newly-local weighting, rigidity, damping, fixed/dragged nodes and integration caps retain their original owners. Degree zero/one has no angular force; both cyclic gaps contribute for degree two.

An independent length spring adds `−k · rigidity · (ρ − L) Wv / ρ`, with `ρ = sqrt(D² + 1)`. It derives from `k · rigidity · (ρ − L)² / 2`, resisting both compression and extension. The one-unit soft core gives isolated target distance `sqrt(L² − 1)` (119.996 at L=120), rather than a singular gradient. This is an explicit extension: the old attraction force has no positive rest length and increasing its multiplier shrinks the star.

The default **Tree structure** preset is `springMultiplier = 1`, `radialStiffness = 1`, `radialLength = 120`, `angularStiffness = 10000`. **Attraction only** retains the earlier multiplier 3, radial stiffness 0 and angular stiffness 300. Its name refers to the radial mechanism; angular reinforcement remains on. Both preserve current focus and coordinate weights. Defaults use weights `{x: 1, y: 1}`. These are tuning choices. The multiplier is finite in 1–100, radial stiffness in 0–2, focal length in 10–1000, angular stiffness in 0–100,000, and each coordinate weight in 0.01–100. Configuration validates the complete update before mutation, copies nested weights, wakes the layout and publishes detached snapshots. Metric weights belong to the derived focal star; low-level callers pass them to `collectFocalStar(graph, center, weights)` before applying its forces.

The paper introduces weighted distance with the longitudinal approximation in equation (2). This port retains equation (1)'s direct angular law and applies the same metric to its angles and radial potential, deriving forces in physical coordinates. This is an explicit adaptation rather than a switch to the pairwise approximation. The attraction preset with unit weights retains the first implementation's numerical behavior; the new default deliberately adds a target length and stronger angular reinforcement.

Explicit persistent tree/DAG/cluster membership, multiple centers and shared-branch handling extend this primitive; see [the substructure and clustering design](rfc-substructures.md). Clusters use degree-normalized internal links, independent two-sided spring rigidity and an unanchored weighted-centroid soft extent, without angular targets. Smooth translucent enclosures show current displayed membership; see the [cluster force contract](rfc-clusters.md). Optional [ellipse exclusion](rfc-exclusion.md) now covers context and non-shared intersection members, with separate controls and force settings. [Structural focus + context](structural-focus-context.md) now adds reversible type filters and leaf aggregation, with the source neighborhood retained independently of the presented membership. Weighted geometry does not promise an empty focal region or readable arbitrarily high-degree stars. RFC settings/activation remain transient and are not serialized as semantic data or view settings.

## Node and link importance

Model weights now control added RFC stiffness independently of the coordinate metric and ordinary TouchGraph physics. Normalize nonnegative weights with `s(w; d) = 2w/(w+d)`, using node default 1 and relation default 10. A relation coefficient `sqrt(s(u)) sqrt(s(v)) s(e)` multiplies added attraction and length stiffness; neighboring angular moments use the geometric mean of their relation coefficients. Defaults preserve existing numerical results exactly. Zeros disable corresponding reinforcement without deleting semantic context or leaving angular ghost branches. The coefficients are bounded, not mass changes.

The [importance contract](rfc-importance.md) specifies energy gradients, zero/member/halo semantics, shared and multigraph behavior, the DAG incoming-relation mean, live updates and limitations. This completes TODO 3.2.7. The Java prototype did not supply an active, consistent node/link force-weighting implementation; the bounded mapping is an explicit 2026 extension rather than a claimed port of a 2005 equation. Optional [focal-region exclusion](rfc-exclusion.md) is now implemented separately, preserving earlier comparisons with it disabled.

## Interaction, halos and solver limits

Once RFC is enabled, repeated Return or double-click on the existing lens center transfers the reinforced focus and wakes the damper. A first center command on another node retains the existing RFC focus. Navigation calls an optional panel extension, so it does not import the RFC module or change plain TouchGraph behavior. Disabled RFC stays disabled. Focal membership is shown with blurred yellow silhouettes/paths in the first edge-layer child, below all semantic edges and nodes; SVG Gaussian blur creates a fading halo without a rim. The group is noninteractive and aria-hidden. A controller listener queues a coalesced repaint for paused updates and detaches on destruction.

A stiffer spring can destabilize the legacy explicit update. For a smooth positive-curvature mode κ and constant damper d, its local recurrence has trace `1 + d/2 − dκ` and determinant `d/2`, giving the stability condition `0 < dκ < 2 + d`. A freely moving regular six-branch star has radial curvature up to `4k`, versus `k` with a pinned center. Caps, context forces and adaptive damping complicate this local result. The [second draft paper](papers/rfc-revisited-draft2.md) derives the equations, compares ablations and records a lower-rigidity experiment. The default remains fixed-force RFC; the separate opt-in damping experiment is described below.

## Adaptive local damping: current detector

`RfcStabilizer` observes actual per-step movement of each movable focal member. It no longer requires a majority of the union's motion energy: a small unstable subgraph cannot be outvoted by a faster translating center. Three persistent reversal votes within eight steps trigger a backoff. Both movements must exceed 0.1 units, the new magnitude must be at least 80% of the previous one, and their normalized dot product must be below −0.1. This retains translation/tiny-jitter/quickly-decaying controls while admitting smaller oscillations and less extreme turns than the first detector.

A second test catches circulation without sharp reversals. In an 8-, 16- or 32-step window, mean movement in each half must exceed 0.1, the second half must retain at least 80% of the first half's travel, and net displacement must be below 35% of total travel. This is a heuristic for persistent inefficient motion, not a spectral estimate. Slow drift with a small oscillatory component and periods outside these windows can still escape it.

A detection halves the multiplier on accumulated focal impulses. When the triggering member is swinging by at least ten units, the next gain also targets a raw requested displacement of two units, subject to a numerical floor of 1e-8. This responds to large hidden impulses behind the legacy displacement cap; it is not a hard bound on all future steps. The former fixed floor of 1/256 could leave stiff modes underdamped. Fixed/dragged nodes are not attenuated. With optional region exclusion enabled, nearby context candidates join the watch/attenuation union so boundary-crossing motion stays observable; distant context remains excluded. Dragging one focal member now excludes that member while continuing to monitor the others, rather than bypassing the whole union.

Gain multiplies focal-node `dx/dy` after RFC forces have accumulated, damping retained momentum and earlier ordinary forces as well as RFC. Force constants and equilibria remain unchanged in the local idealization. Other force callbacks registered after RFC execute after this attenuation.

Recovery retains the 500 ms quiet interval and 3000 ms cubic easing. Motion above 0.1 during recovery immediately rolls gain back to the gain at recovery's start, rather than retaining the partially reheated value until another detected episode. Pauses over 250 ms, clock regression and membership changes discard motion history; elapsed contributions are capped at 50 ms. A dragged member is excluded, with the membership change restarting observation once. The existing optional `LayoutForce.needsTicks()` hook advances recovery even when ordinary global cooling has stopped motion; it does not restart an explicitly stopped runner.

The experiment remains **off by default**. Enable **Experimental adaptive damping**, call `rfc.setStabilizationEnabled(true)`, or pass `rfcStabilization: {enabled: true, now?: () => milliseconds}` to `FreshmindPanel`. `getState().stabilization` reports phase/gain, detection count, last trigger, affected node IDs, recovery backoffs and maximum observed movement. The source UI reports when detection is disabled, and exposes these diagnostics when enabled. Force settings and activation remain transient.

The [detector and response comparison](experiments/rfc-stability/README.md) reproduces the two old blind spots and tests small two-center stars, overlapping weighted clusters and two recorded multiple-tree starts. Original [Experiment B](experiments/rfc-single-focus/README.md#experiment-b-adaptive-local-damping) and its paper/figure results retain their frozen v1 detector under `tests/fixtures/rfc-stabilization-v1.mjs`, sourced from commit `d0fa69a`. This archive is used only by research fixtures and is not part of the browser/library. `just rfc-experiment` still reproduces those historical records exactly; `just rfc-stability-experiment` compares v1/current detection separately. Neither quiet motion nor restored gain proves an accurate or feasible layout.

[Experiment F](experiments/rfc-followup/damping/README.md) compares v2 damping with global rigidity 1/0.5/0.25/0.1 on all five recorded starts and both root constraints (240 runs). Its final-coordinate probe disables local attenuation, clears momentum, prevents movement and measures existing TG+RFC forces, normalized by rigidity. This exposes cooling with residual imbalance and force-balanced compromises with infeasible targets. On the movable leaf-linked starts, low rigidity often reaches a better balance than damping at full rigidity. No production default or integration rule is changed by the experiment; lower rigidity and local damping remain distinct controls.

## Optional focal-region exclusion

The [exclusion contract](rfc-exclusion.md) implements the 2005 paper’s ordinary-context exemption and non-shared intersection policy. It fits physical ellipses around eligible visible memberships, chooses a single bounded escape from applicable region unions and distributes reactions to roots/centroid anchors. Context inside several areas does not receive mutually canceling per-region pushes. Shared members are exempt from their own regions; ellipses can still overlap.

`configureExclusion({enabled, overlap, strength, padding})` owns independent transient settings, off by default. `getState()` returns detached settings/region geometry; panels accept `rfcExclusion` constructor options. Reusable controls and the main browser’s Focal regions section expose these settings, and dashed paths follow all current lenses without affecting picking. [Experiment I](experiments/rfc-exclusion/README.md) retains 100 matched runs and three diagrams, including pinned intruders, all-step exposure, force balance and limited additional overlap benefit. This is point-based soft exclusion, not label collision or a hard feasible-region solver.

## Structural focus + context

The [structural view contract](structural-focus-context.md) implements the hybrid mechanism from §2.3 of the paper. Semantic leaf types aggregate outside protected detail and expose typed parent counts; explicit node/relation filters take precedence. The complete graph and stored memberships remain unchanged. TG neighborhood traversal uses its existing source membership; rendering, physics, picking and RFC share the derived view. Hidden centers suspend and can resume; activating a stored structure restores its eligible aggregated detail. Controls, E/reveal/reset, a synthetic native example and library APIs are included. Rules remain transient and default off. [Experiment J](experiments/rfc-hybrid/README.md) adds 160 matched TG/RFC/lens/view conditions with common retained-constraint scores and exact physical lens twins. Original-figure reproduction is outside the agreed scope; these finite comparisons do not establish perceptual benefit or general convergence.

## Importance display

[Node importance display](rfc-importance.md#node-importance-display) now provides bounded body/label scaling around default weight 1, uniform/legacy modes and optional exact values. Type/item configuration persists in YAML; transient panel preferences can override it. Actual measured dimensions drive picking, shape-matched focus, curve clipping, cluster boundaries and silhouette halos. The display neither wakes integration nor changes ordinary/RFC forces. Yellow glow retains its independent participation meaning. This completes 3.2.18 without adding a perceptual-evaluation claim.
