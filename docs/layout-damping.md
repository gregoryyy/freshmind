# Adaptive layout damping

**View → Layout motion → Adaptive damping** starts enabled in the main browser. It observes all movable visible nodes and suppresses repeated swings independently for each node, with or without RFC. Steadily moving context nodes retain their own response while an RFC node oscillates. The status below the checkbox shows whether observation is enabled, the current impulse gain and confirmed detections. Disabling it restores ordinary TouchGraph cooling; pausing motion still stops integration.

The detector runs inside `TGLayout`, after every registered force callback and before position integration. It scales accumulated impulses, including retained momentum, rather than changing spring/repulsion coefficients or node coordinates directly. Fixed and dragged nodes are excluded. Each node owns its gain, motion history and recovery clock. The displayed gain is the minimum across active nodes, not a multiplier applied to the whole graph. One oscillating node does not attenuate another node’s impulses or block its recovery. This is separate from viewing lenses, canvas zoom and label arrangement.

**Damping response** offers two choices. **Adaptive impulses** is the default and applies the extra gain described here. **Earlier TouchGraph cooling** observes the same cycles but applies no extra impulse gain: it caps the inherited damper at 0.89 after a confirmed detection, entering the existing faster cooling phase. During persistent large motion the original rule decreases the damper by only 0.0001 per eligible step until it is below 0.9, then by 0.01. This explains the long delay followed by sudden settling. Earlier cooling retains the rest of that rule, respects explicitly disabled TG cooling and does not anneal gain back up. The experiment compares both responses and their transient/balance trade-offs.

Fast motion retains the per-node reversal and 8/16/32-step circulation tests from the earlier RFC experiment. Slower motion also tracks four alternating extrema on each coordinate axis. A return greater than 0.2 physical units confirms an extremum. The last two excursions must each retain at least 80% of the preceding amplitude, with net endpoint displacement below 35% of the three-leg path. Only four extrema per axis are retained. The recorded slow probes trigger after roughly two cycles, including movement whose individual steps stay below 0.1 units. Translation, tiny jitter and rapidly decaying controls remain undamped in the tests. These thresholds are heuristics, not a general oscillation classifier.

A detection halves gain; large swings can trigger a stronger reduction based on the next requested impulse. After 500 ms of quiet observed integration, gain recovers over three seconds. Movement of that same node interrupts its recovery and rolls it back; movement elsewhere does not. **Recovery duration is distinct from the time until oscillation is suppressed.** Clock gaps discard stale motion history. Hidden, removed, fixed and dragged nodes release their local history/gain; other nodes keep their own observation windows. Clearing/replacing the document resets all learned gains while retaining the enabled preference. Recovery uses the existing runner and never restarts an explicitly paused layout.

Library panels preserve legacy defaults. Opt in with `adaptiveDamping: {enabled: true, now?: () => milliseconds}` in `TGPanel`/`FreshmindPanel` options, or supply those options as the third `TGLayout` constructor argument. `layout.setAdaptiveDampingEnabled(boolean)` changes the setting; `getAdaptiveDampingState()` returns detached diagnostics, and `resetAdaptiveDamping()` clears learned state. `bindMotionControls` in `fm4/fm/ui` binds caller-owned controls and returns listener cleanup.

Set `response: "cooling"` in those options or call `setAdaptiveDampingResponse("cooling")` for earlier inherited cooling; `"impulse"` restores the default response. `getAdaptiveDampingResponse()` reports the choice. In observation-only cooling mode, the detector's reported impulse gain is diagnostic and never multiplies node impulses; the UI reports the inherited TG damper instead. Earlier cooling remains a global response and can slow context clearing. Both choices and the enabled preference survive document replacement; learned history/gain are reset. Restoring a showcase's common initial coordinates also resets learned state.

The original RFC-local `rfcStabilization` option, `RfcStabilizer` and control bindings remain available with their previous sampling behavior and numerical records. The main browser leaves that separate controller disabled and uses general damping once, after all forces. RFC activation/removal does not toggle general damping.

For historical replay, `scope: "graph"` in the layout options selects the former common gain. The default is `scope: "node"`. `NodeMotionStabilizer` supplies independent gains; the original `MotionStabilizer` and RFC-local experiment remain available with their existing contracts. No additional browser scope toggle is introduced.

[Experiment L](experiments/damping-context/README.md) records twelve controlled comparisons of context drift/RFC clearing under shared and independent gains, with inherited cooling off/on. A browser regression measures actual label rectangles: a context label can clear the focal label while a prescribed focal branch keeps swinging. This isolates damping cross-talk; exclusion remains center-based, and damping does not guarantee collision-free labels. A node that itself oscillates can still be attenuated, and inherited cooling can leave residual error.

The historical [Experiment K](experiments/layout-damping/README.md) compares native TG and stiff RFC layouts with extra damping off/on, separates the new slow detector from wider observation, and distinguishes first detection, last substantial movement and full recovery. The [paper](papers/rfc-revisited-draft2.md#54-general-layout-damping-and-experiment-k) discusses its relation to the discrete update. Low movement does not establish force balance, feasible constraints, readable labels or convergence on arbitrary graphs.
